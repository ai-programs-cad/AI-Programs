# CNC File Doctor 0.7.0

Автономная программа для диагностики DXF, аппроксимации сплайнов и разделения объектов по слоям. Для обработки DXF не нужны SolidWorks, AutoCAD, интернет или отдельная установка Python. Распакуйте весь архив и запустите CNC File Doctor.exe. Требуется Windows с .NET Framework 4.5 или новее. Проверено на текущем компьютере; отдельная проверка на чистой Windows ещё не выполнена.

## Где находятся результаты

Выберите DXF или папку. Программа автоматически создаст папку внутри папки исходных файлов: например, `1.5 mm\1.5 mm_1`, при следующем запуске — `1.5 mm\1.5 mm_2`. Существующие папки не перезаписываются. Если выбраны файлы из разных папок, результаты сохраняются отдельно в каждой из них.

Готовые DXF лежат прямо в пронумерованной папке. Кнопка **Обработанные файлы** открывает папку результата выбранной строки. Поле «Папка результатов» показывает её путь. Кнопка **Открыть отчёт** открывает отчёт по выбранному результату.

- EXACT — точные копии исходников с проверкой хеша.
- Reports — отчёты HTML/JSON, подробности проверок, карта распределения по слоям и журналы.
- Quarantine — созданные, но не прошедшие проверки варианты; не используйте их для резки без дополнительной проверки.

При выборе папки её предыдущие результаты не включаются в пакет повторно. Если намеренно выбрать саму папку результата, будут загружены только DXF непосредственно в ней, без EXACT/Quarantine. Исходники не перезаписываются.

## Проверка и CAM_ARCS

**Проверить** выполняет диагностику. **Создать CAM_ARCS** создаёт файлы `-CNC.dxf`. Для аппроксимации сплайнов сначала обеспечиваются плавные стыки и заданное отклонение, затем сокращается число дуг и отрезков. Поле «Макс. отклонение, мм» позволяет выбрать значение или ввести своё через запятую или точку; по умолчанию 0.01 мм. Меньшее значение обычно требует больше дуг и времени. Глобальный минимум не доказан. Используются сертификаты погрешности по всей кривой и повторная проверка записанного DXF. Финальные контуры резки обязательно проверяются на замкнутость в пределах 0.001 мм; более строгие существующие проверки движка также сохраняются. Контроль замыкания не перемещает вершины и не добавляет перемычки. UP/DOWN считаются слоями сгиба, а не замкнутой резки. Слои резки по умолчанию `0`; несколько имён вводятся через запятую.

Преобразователь поддерживает ограниченный набор плоских миллиметровых ASCII/UTF-8 DXF: LINE, ARC, CIRCLE, SPLINE и прямые нулевой ширины LWPOLYLINE в выбранных слоях резки. Прямые полилинии разворачиваются в отрезки с точным сохранением координат. Дуговые полилинии, ненулевая ширина/высота/толщина, блоки и другие неподдерживаемые данные отклоняются. Максимальный размер входа 100 MB; процесс преобразования ограничен 180 секундами на файл. Все варианты требуют проверки в целевой CAM-системе перед резкой.

## Разделение по слоям

Нажмите **Разделить по слоям** и отметьте признаки: цвет, тип линии, толщина линии, тип объекта. Создаётся отдельный файл `-LAYERS.dxf`; геометрия не меняется. Учитываются явные свойства объектов и свойства ByLayer исходного слоя, в том числе TrueColor. Состояние видимости/заморозки/блокировки/печати исходных слоёв сохраняется как обязательное различие групп. Свойства линий делаются явными, чтобы перенос на другой слой не изменил оформление.

Поддерживаются верхнеуровневые LINE, ARC, CIRCLE, SPLINE, LWPOLYLINE, ELLIPSE, TEXT, POINT, SOLID, TRACE и 3DFACE. Группы сравниваются по фактическим свойствам независимо от способа назначения (явно, ByLayer или верхнеуровневый ByBlock). Типы линий сравниваются по рисунку, а не имени. Исходные ByBlock-записи сохраняются без подмены. Внешняя настройка толщины по умолчанию не угадывается; без записанного значения она не приравнивается к произвольной числовой толщине. INSERT/блоки, составные POLYLINE, DIMENSION, MTEXT, HATCH и MULTILEADER в смешанном файле сохраняются на исходных слоях без изменения записей; отчёт явно отмечает частичное распределение. Если нет ни одного поддерживаемого объекта, разделение не выполняется. Некоторые расширенные данные по-прежнему могут блокировать обработку. Это распределение по оформлению, а не автоматическое определение технологического назначения: программа не угадывает, где резка, гравировка или сгиб.

Просмотр показывает отрезки, дуги, окружности, прямые полилинии и выборку исходных сплайнов; после обработки можно сравнить источник с созданным результатом. Другие типы могут не отображаться.

## Разработка и проверки

Исходники, тесты, синтетические примеры и build.ps1 включены. База движка — исходная сборка PartCraft. Локальное расширение поиска меньшего числа элементов описано в docs/engine-local-changes.json; происхождение базовых модулей — в docs/engine-provenance.json. Установленный PartCraft не изменяется. В комплекте 99 тестов базового движка и 55 тестов приложения; проверены интерфейс и копии реальных DXF. Это рабочая развивающаяся версия: установщик, подпись, Free/Pro-лицензирование и полная приёмка на чистой Windows/целевых CAM ещё не завершены. Лицензия Python находится в runtime/LICENSE.txt; лицензия на пользовательские исходники не назначалась.

CLI с явно заданной новой папкой остаётся доступен:

```powershell
.\runtime\python.exe -I .\src\doctor.py --input 'D:\part.dxf' --output 'D:\results\new-job' --convert --tolerance-mm 0.01 --cut-layer 0
```

В этом совместимом CLI-режиме результаты сохраняются в указанной папке с подкаталогом CAM_ARCS. Автоматическое расположение рядом с источниками применяется в Windows-интерфейсе. Код завершения 0 означает завершение диагностики без отмеченных проблем, 1 — ошибку, 2 — замечания или вариант, требующий проверки. Ни один код не подтверждает готовность для станка.


## Улучшенный просмотр 0.7.0

Область чертежа увеличивается вместе с окном; границу с пояснениями можно перетаскивать. Колёсико меняет масштаб, левая/средняя кнопка перемещает чертёж, двойной щелчок или «Показать целиком» возвращает общий вид. «К отметке» приближает следующую проблему или изменённый участок. В списке «Исходный DXF / Результат» можно сравнить файлы. Отображаются также сплайны — как выборка только для просмотра, не для расчёта допуска.

Красные значки «!» — найденные проблемы; пояснение появляется при наведении. Жёлтым выделяются исходные сплайны и полилинии, зелёным — реально заменённые элементы результата. Непочиненные проблемы остаются красными, а неподтверждённый файл — в карантине. Включение/выключение «Маркеры» переключает эту подсветку. Цвет самой линии может быть красным по исходному DXF и не означает проблему без маркера. Сохраняются TrueColor и различия основных индексных цветов, с адаптацией контраста для тёмного фона; прочие ACI пока показаны нейтральным цветом. Сам DXF от просмотра не меняется.

Показываются обнаруженные открытые концы, ветвления, нулевые отрезки, некорректные радиусы, совпадающие записи и объекты с неподтверждёнными пересечениями по отчёту движка. Это не исчерпывающая визуальная проверка всех дефектов. Ограниченный или неподдерживаемый просмотр отмечается явно. Программа не выдаёт найденные, но не устранённые дефекты за исправленные.



В 0.7.0 просмотр поддерживает также дуговые участки LWPOLYLINE: внешний контур и фигурные вырезы больше не пропускаются. Это исправление отображения; преобразование таких полилиний в CAM_ARCS пока остаётся заблокированным. Красные окружности исходного DXF являются обычной геометрией; только отдельный ромб со знаком «!» обозначает проблему.



## Наружные и внутренние контуры

В проверке поддерживаемых замкнутых контуров и после преобразования определяются наружные контуры, отверстия и островки. Вложенность учитывает несколько отдельных деталей и несколько уровней отверстий. В режиме «Контуры» наружные линии голубые, отверстия жёлтые, островки фиолетовые. Переключатель отключает эту подсветку; геометрия и слои DXF не меняются. Номера контуров, родительский контур и глубина вложенности записываются в пояснения и отчёт. Открытые, пересекающиеся или неподтверждённые контуры не объявляются проверенными.


## Единые замкнутые контуры

После успешного CAM_ARCS создаётся готовый файл `-CONTOURS.dxf`: каждый контур объединён в одну замкнутую LWPOLYLINE, дуги записываются через bulge и не превращаются в короткие отрезки. Окружность уже является единым замкнутым объектом и сохраняется как CIRCLE. Наружный контур и отверстия остаются отдельными объектами. «Открыть DXF» открывает готовый файл в назначенной Windows программе. Контрольная версия из ARC/LINE сохраняется в Reports/*-analytic.dxf. Геометрия полилиний проверяется после записи; дополнительная погрешность входит в общий заданный допуск. Проверяются плавность стыков, пересечения и сохранение вложенности. Разные свойства внутри контура, ссылки, расширенные данные или неподтверждённая геометрия могут блокировать объединение; причина указывается явно, контрольный результат не выдаётся за объединённый. Это не автоматическое устранение произвольных разрывов.


## Интерфейс 0.7.0

Основное действие — «Обработать DXF»: аппроксимация, проверки и объединение в единые контуры. Карточка результата показывает статус, наружные контуры/отверстия/островки, число замкнутых объектов, фактическое отклонение и сохранность исходника. «Проверки пройдены» не заменяет проверку в целевой CAM-системе. На время обработки видны прошедшие минуты и секунды; окно остаётся доступным для изменения размера.

DXF и папки можно перетаскивать в окно; Ctrl+O добавляет файлы, Ctrl+Enter запускает обработку, F5 — проверку. Список показывает короткие имена; полный путь доступен при наведении. Интерфейс переключается между русским и английским. Минимальное окно — 1100×820; проверены оба языка, увеличение/уменьшение, состояния ожидания/обработки/ошибок и открытие результата через соответствующую кнопку. Внешние CAD/CAM-приложения автоматически в тестах не запускались. Движок обработки идентичен версии 0.6.2.
